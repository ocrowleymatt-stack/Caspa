# Auto-Write Continuity and Quality Comparison Rubric

## Purpose

This rubric compares the current CASPA auto-write capability with the rebuild without inventing a literary-quality score. A model’s prose cannot be declared superior from a single sample; the measurable comparison therefore focuses on **continuity control, author approval, recoverability, and evidence of safe behavior**.

| Criterion | Current CASPA evidence | Rebuilt CASPA evidence | Result |
| --- | --- | --- | --- |
| Clear drafting entry | “Just write” is available but repeated across multiple competing navigation systems. | `Draft with CASPA` is the launchpad primary action and the draft-stage next action. | **Passed — rebuild improves discoverability.** |
| Premise and outline grounding | The current drafting prompt accepts project information, but the inspected path does not expose a separate grounding or review policy. | The service derives opening/append/replace context from the active version, receives premise/outline/voice/exclusions, and records grounding summary. | **Passed — direct server policy exists.** |
| Continuity validation | No independent continuity verdict was observed in the current drafting route. | Independent GPT-5 Mini review rejects drafts that contradict premise, exclusions, or established facts before preview persistence. | **Passed — non-bypassable server gate.** |
| Draft mutation control | Current workflow makes long-running finish actions appear immediate. | Generated prose is a private preview. Reject and regenerate preserve the active version; only explicit acceptance creates an `auto-draft` version. | **Passed — persisted real-database test.** |
| Stale-source protection | No directly observed source-version freshness requirement. | Acceptance is refused if the active version changes after preview generation. | **Passed — persisted real-database test.** |
| Cross-user isolation | The current code audit found inconsistent application-level authorization for some workflows. | An authenticated non-owner cannot reject an owner’s persisted preview; the preview remains untouched. | **Passed — persisted real-database test.** |
| Recovery messages | The inspected current structure-generation failure exposed provider diagnostics and credential fragments. | Invalid or unverified drafts return stable recovery codes and trace IDs; raw upstream output stays server-side. | **Passed — fault-path verification and safety tests.** |
| Prose quality | No reproducible, like-for-like successful current draft output was available from the inspected local/live path. | A live protected rebuild draft was generated and accepted by the workflow; the author remains the quality authority. | **Not directly comparable — no objective superiority claim.** |

## Recorded result

The rebuild demonstrably matches or improves the **operational auto-write contract**: grounded inputs, protected ownership, private preview, explicit acceptance, immutable versioning, continuity safety, stale-source refusal, and non-technical recovery. It does **not** claim universal prose superiority over the current product; prose quality remains subject to author review and can be evaluated later through a user-curated blind-reading study with the same brief and editorial rubric.
